# D02 | API Development and Integration Programme

| | |
|---|---|
| **Organisation** | Listed West African IT services group |
| **My role** | Senior Product Manager, owning the programme operating model |
| **Scale** | 100+ API development, customisation and integration initiatives |
| **Customers** | 16 financial institutions |
| **Focus** | Repeatable delivery model, Agile delivery, release control |

## Context

Financial institutions kept asking for API work and platform customisation. Handled one by one, each request risked becoming a bespoke project with its own surprises, and customisation debt was building up.

## What I did

Set up one operating model for every request:

1. **Standard intake** so each request arrived with the same minimum information
2. **Requirements workshops** with the customer and technical leads
3. **Estimation and backlog** entry, prioritised against other committed work
4. **Sprint delivery** with a traceability matrix linking requirements to tests
5. **UAT with entry and exit criteria** agreed with the customer in advance
6. **Release calendar and change approval** so releases did not collide
7. **Deployment checklist** for every go-live
8. **Early life support** followed by a post-implementation review

To keep customisation debt under control, each new request was checked for reuse, and repeated requests were reviewed for productisation into the standard platform.

## Results

- **100+** initiatives delivered across **16** financial institutions
- A single, repeatable delivery model in place of bespoke projects
- Customer requirements turned into prioritised, testable technical work

## What this shows

- Agile delivery at programme scale in regulated environments
- Governance that speeds delivery rather than slowing it
- Product thinking applied to delivery: reuse and productisation
